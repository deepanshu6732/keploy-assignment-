<h2 id="1-prerequisites">1. Prerequisites</h2>

Before we get started, make sure your environment is ready:

- **Go** (1.16 or higher)
- **Keploy CLI**

<Callout type="info" title="Installing Keploy CLI">
If you haven't installed Keploy yet, you can do it in seconds from the terminal:

```bash
curl --silent -O -L https://keploy.io/install.sh && source install.sh
```
</Callout>

## 2. Set up the sample application

Let’s build a compact Go HTTP server and expose one endpoint to demonstrate the flow clearly.

```bash
mkdir keploy-go-sample && cd keploy-go-sample
go mod init keploy-go-sample
```

Create a `main.go` file with the following API handler:

```go
package main

import (
    "encoding/json"
    "net/http"
)

type Response struct {
    Message string `json:"message"`
    Status  string `json:"status"`
}

func helloHandler(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(Response{
        Message: "Hello from Keploy!",
        Status:  "success",
    })
}

func main() {
    http.HandleFunc("/api/hello", helloHandler)
    http.ListenAndServe(":8080", nil)
}
```

<Callout type="warning" title="Graceful Shutdown">
For Keploy to save recorded tests and coverage cleanly, your app should shut down gracefully on `SIGINT` and `SIGTERM`. In a production service, always add proper lifecycle handling around your server.
</Callout>

---

## 3. Record traffic with Keploy

Instead of writing tests manually, start the app in **record** mode and let Keploy watch your real traffic.

```bash
keploy record -c "go run main.go"
```

Once the server is running, make a few requests to the endpoint with curl, Postman, or your browser:

```bash
curl http://localhost:8080/api/hello
```

### What happens behind the scenes?

As you interact with the app, Keploy captures the HTTP method, request headers, payloads, and the resulting response. It stores those interactions locally as YAML test artifacts, typically in a `keploy` directory within your project.

<Callout type="success" title="The “aha” moment">
This is where Keploy becomes incredibly powerful: by using the app the way real users do, you create realistic regression coverage without writing repetitive mock code by hand.
</Callout>

---

## 4. Replay and validate

When you’re ready, stop the server with Ctrl+C and run the replay flow.

```bash
keploy test -c "go run main.go" --delay 10
```

*The `--delay` flag gives the server a moment to start before Keploy executes the recorded requests.*

Keploy launches your app, replays the exact traffic it captured earlier, and compares the new responses against the saved baseline. You’ll get a clear pass/fail signal for each scenario.

<h2 id="5-why-keploy">5. Why Keploy?</h2>

If you’ve built Go APIs before, you know the cost of manual test setup: boilerplate table-driven cases, flaky stubs, and Docker-heavy integration loops.

Keploy removes that friction:

- **Time Savings**: Generate test cases from your actual traffic in minutes, not hours.
- **Accurate Mocks**: Recorded database and external calls are turned into realistic mocks during replay.
- **High Coverage**: Test real-world behavior instead of synthetic scenarios that only partially reflect production.

<div className="benefit-box">
  <strong>Practical outcome:</strong> you spend more time shipping features and less time chasing false confidence from brittle tests.
</div>
